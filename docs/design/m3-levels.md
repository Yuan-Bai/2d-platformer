# M3 设计：狐跃林间 · 关卡内容

> 阶段 0 交付物。锚定于 2026-08 的架构会话（grilling 两轮 + 命名确认）。
> 关联：CONTEXT.md（术语表）、docs/adr/0001~0008（ADR）、ADR-0006（关卡数据格式）、ADR-0007（流转）、ADR-0008（表现层）。

## 1. 范围与锚定决策

M3 = 教学关 + 3 正式关的关卡内容：4 个可连续通关的场景，统一 Sunny Land 森林主题（不引入新素材），休闲为主、关3 稍难。

| 决策 | 结论 |
|---|---|
| 分工 | 混合：关卡初版由生成器从 JSON 数据生成（保证可通关），用户试玩后在编辑器微调 |
| 通关目标 | 终点门 + 可选樱桃（无门槛收集支线） |
| 流转 | M3 内置：终点门 → 下一场景；关3 → 通关占位画面（ADR-0007） |
| 玩家外观 | Foxy 进 M3，状态机驱动动画（ADR-0008） |
| 教学提示 | 世界内像素路牌 + 中文 UI 提示（淡出）；文本用 legacy Text（系统字体回退渲染中文），M4 可升级 TMP + CJK SDF 字体 |
| 命名 | 游戏名「狐跃林间 / Foxy's Forest」；关卡名见第 5 节 |
| 难度 | 休闲：重生点密、无收集门槛；关3 允许 1~2 段挑战 |
| 动作集 | 冻结：冲刺/滑墙/爬墙/二段跳留待 M4 后的 M5（本会话决议），M3 关卡按现有动作集设计 |

## 2. 关卡度量基准（可通行性数字）

由 `PlayerMotor.Settings`（M1 调校值）推导，生成器与关卡数据都锚定这组数字：

| 指标 | 数值 | 推导 |
|---|---|---|
| 满速 | 6 m/s | MaxSpeed |
| 单跳最大高度 | **2.52m** | v²/(2g) = 11²/(2×24) |
| 满速平跳最大跨度 | **≈5.0m** | 满弧空时 0.843s × 6 m/s |
| 原地起跳最大跨度 | ≈4.4m | 空中加速 28 m/s² + 满速巡航 |
| 弹簧弹起高度 | **≈2.9m** | 14²/(2×34)（Bounce 全程下落重力） |
| 弹簧平跳跨度 | ≈4.9m | 空时 0.82s × 6 m/s |
| 下落后终端速度 | 16 m/s（>3.8m 的坑无差别） | MaxFallSpeed |

**设计红线（生成器与关卡数据的约束）**

- 相邻平台间隙：关1/2 ≤ 3.5m，关3 挑战段 ≤ 4.5m（需满速/空中控制），其余 ≤ 3m。
- 单跳上台高度：关1/2 ≤ 1.8m，关3 挑战段 ≤ 2.2m；弹簧上台 ≤ 2.6m。
- 天花板净高 ≥ 2m（新盒高 1.6 + 容差，ADR-0008）。
- 所有深坑底部铺尖刺：项目无 kill plane 机制（ADR-0005 不新增机关类型），坑底尖刺保证坠落必死重生。
- 图块基准：tileset.png 为 400×368 = **25 列 × 23 行**（16px 网格，PPU 16，透明格已排除、共 128 个用户切片 `tileset_0..127`，pivot center）→ 1 图块 = 1 世界单位 = ASCII 地图 1 字符（ADR-0006）。切片归用户所有（Sprite Editor），生成器只消费 `Assets/Tiles/*.asset`。
- 地形选块规则（用户目视确认）：`tileset_0~2` = 草顶岩石（表面块），`tileset_3` = 纯岩石（内部块）。`#` 地形：上方无 `#` 的单元格用草顶块（0~2 轮换取变化），其余单元格用纯岩块。

## 3. 关卡数据格式 v1

位置 `Assets/Levels/{scene}.json`，一份文件 = 一个场景的完整源数据。元数据结构化，用 Unity 内置 `JsonUtility` 反序列化（零外部依赖）；地形保留 ASCII 行数组，严格 1 字符 = 1m。

```json
{
  "name": "第一步",
  "scene": "01-Tutorial",
  "background": ["back", "middle"],
  "movingPlatforms": [
    { "waypoints": [{ "x": 2, "y": 0 }, { "x": 6, "y": 0 }], "speed": 1.5 },
    { "waypoints": [{ "x": 0, "y": -3 }, { "x": 0, "y": 3 }], "speed": 2.0 }
  ],
  "signs": ["移动", "跳跃"],
  "map": [
    "...........P..............",
    "....#########.....c...####",
    "....#...........==..==..D#",
    "....#..S...S....M...M....#",
    "####X#####################"
  ]
}
```

**地图图例**（map 首行 = 地图最顶行；每行等长；严格 1 字符 = 1m，多实例机关用出现顺序对应元数据数组）：

| 符号 | 含义 |
|---|---|
| `#` | 实心地块（tilemap 正式地形） |
| `=` | 单向平台 |
| `.` | 空 |
| `P` | 玩家出生（恰 1 个） |
| `D` | 终点门（恰 1 个） |
| `C` | 重生点（≥1 个） |
| `B` | 弹簧 |
| `M` | 移动平台（第 n 个对应 `movingPlatforms` 第 n 项） |
| `X` | 尖刺 |
| `c` | 樱桃 |
| `S` | 教学路牌（第 n 个对应 `signs` 第 n 项） |

**结构校验（`LevelValidator`，EditMode 测试随生成器交付）**：JSON 可解析、P/D 各恰 1、C≥1、M/S 数量与元数据条目数一致、map 行等长且只含图例字符、出生点 2m 内无 X、左右边界列全为 `#`、每列必须有可站立表面（坑必有底）、**尖刺连续段宽度 ≤ maxGap**（难度默认表 tutorial 3 / easy·medium 3.5 / hard 4.5 米，JSON `maxGap` 可覆盖；项目设计约定"坑底全铺尖刺"，故尖刺段宽 ≈ 坑宽 = 必须空中跨越的距离）。JSON 不支持注释，字段语义以本表为准。

**诚实边界**：上台高度红线与全物理可达性不做——装饰性高墙无法与必经台阶区分，v1 不引入路径分析，这两项靠布置约定 + 用户试玩兜底（§13）。

## 4. 场景与流程

| Build Settings 顺序 | 场景文件 | 内容 |
|---|---|---|
| 0 | `Assets/Scenes/Levels/01-Tutorial.unity` | 教学关「第一步」 |
| 1 | `Assets/Scenes/Levels/02-ForestPath.unity` | 关1「林地小径」 |
| 2 | `Assets/Scenes/Levels/03-SkyBridge.unity` | 关2「云上栈道」 |
| 3 | `Assets/Scenes/Levels/04-ThornForest.unity` | 关3「棘林深处」 |
| 4 | `Assets/Scenes/Levels/05-GameClear.unity` | 通关占位画面 |

**流转行为**（ADR-0007）：终点门接触 → 暂停输入 + 淡出 + 过关统计「本关樱桃 x/y」→ `SceneManager` 加载下一场景（Build Settings 索引 +1）；关3 → 通关画面显示「恭喜通关！樱桃累计 x/27」。累计进度用 `LevelManager` 的 static 字段跨场景传递；M4 接主菜单时把场景 0 换成主菜单，链路语义不变。

**每关场景内装配清单**：主相机 + Cinemachine Brain、`LevelManager`、tilemap 地形、机关与樱桃、玩家（出生点）、VCam + `PlayerCameraRig`（每关 Confiner2D 边界 = 地图范围 + 2m 边距）、两层视差背景、HUD（樱桃计数，legacy Text）、教学路牌 + 提示触发区。

**手工搭关（与 JSON 管线并存，混合分工的另一半）**：`Tools/Platformer/Build Prefabs` 生成 `Assets/Prefabs/` 9 个乐高块（Player/Bumper/MovingPlatform/Spikes/Checkpoint/Cherry/Door/Sign/OneWayPlatform，与生成器共用 LevelKit 工厂装配）；`Tools/Platformer/New Level Scaffold` 生成空场景（相机/VCam/相机边界/背景/HUD/LevelManager/空 tilemap 含碰撞）。流程：Tile Palette 刷地形（`Assets/Tiles` 的 tileset_0~3）→ 拖预制体 → Inspector 配置 VCam 的 Follow Target 与 LevelManager 字段 → Build Settings 加场景。手工场景不经 LevelValidator（校验只覆盖 JSON 管线），质量靠试玩。

## 5. 四关规格（节拍表）

### 教学关「第一步」（01-Tutorial）· ~60s · 樱桃 4 · 重生点 2

| 节拍 | 内容 | 提示（路牌/UI） |
|---|---|---|
| 1 | 平地起跑，无危险 | S1 移动「A / D 或 ← / →」 |
| 2 | 两级台阶（≤1.2m） | S2 跳跃「空格：跳跃。按住空格跳得更高」 |
| 3 | 单向平台栈；下方藏樱桃 | S3 下穿「站在平台上按住 S / ↓ 下落穿过」 |
| 4 | 弹簧上高台；高台有樱桃 | S4 弹簧「踩上去自动弹高，不用按跳跃」 |
| 5 | 移动平台横渡 | S5 平台「跳上去，它会带你走」 |
| 6 | 尖刺段（重生点在前） | S6 危险「碰到尖刺会回到最近的复活点」 |
| 7 | 樱桃串 + HUD 计数展示 | S7 樱桃「樱桃是可选收集，不用全拿」 |
| 8 | 终点门 | S8 出口「到达大门即可过关」 |

### 关1「林地小径」（02-ForestPath）· ~90s · 樱桃 7 · 重生点 3

机制：基础跳跃 + 单向平台。起跑平地 → 连续台阶（≤1.5m）→ 平台跳跃走廊（两处 3m 间隙）→ 单向平台双层上行 → 回头下穿捡支线樱桃 → 短尖刺点缀 → 终点门。

### 关2「云上栈道」（03-SkyBridge）· ~120s · 樱桃 7 · 重生点 4

机制：弹簧 + 移动平台组合。弹簧上楼（2.5m）→ 移动平台横渡（下方尖刺）→ 双弹簧接力 → 移动平台 + 单向平台混合段 → 弹簧回头支线樱桃 → 终点门。

### 关3「棘林深处」（04-ThornForest）· ~120-150s · 樱桃 9 · 重生点 5

机制：全机制综合。热身段（复习）→ 尖刺走廊（乘移动平台穿过）→ **挑战 A**：4.5m 满速跳或弹簧捷径二选一 → **挑战 B**：连续移动平台 + 尖刺 → 收尾放松段 → 终点门。

樱桃分布原则：主路 ~60% 顺手、~40% 需要小绕路/回头；总数 27（4+7+7+9）。

## 6. 教学提示规格

- **世界路牌**：`sign.png`（18×20，PPU 16 → ≈1.1×1.25m）立在教学点旁；文案在关卡数据 JSON 的 `signs` 数组里（第 3 节），生成器用 TMP 叠加在路牌旁。
- **UI 提示**：角色进入提示触发区 → 屏幕下方中文提示条淡入 → 离开或 4s 后淡出。每关首见机制才提示，重复段不再提示。实现选型：legacy `Text`（TMP 默认字体不含 CJK 字形，M4 换 TMP + CJK SDF 字体资产）。
- 重生点视觉 = 木牌 tint（实现期定色），与教学路牌原色区分；终点门 = `door.png`（22×33，≈1.4×2.1m）。

## 7. 玩家表现层规格（ADR-0008）

| 状态 | 动画 | 素材 |
|---|---|---|
| Idle | idle 4 帧循环 | `Foxy/idle/spritesheet.png`（132×32） |
| Run | run 6 帧循环 | `Foxy/run/spritesheet.png`（198×32） |
| Jump | jump 2 帧 | `Foxy/jump/spritesheet.png`（66×32） |
| Fall | **复用 jump 第 2 帧**（素材无独立下落动画） | 同上 |
| 死亡冻结 | 表现冻结当前帧（M2 行为不变） | — |

- 表现由 `PlayerVisuals` 组件驱动：只读 `PlayerBody.CurrentState`，帧循环在代码内完成、状态→动画映射即序列化字段数组（比"生成 AnimationClip 资产"更简：无 Animator 资产、无双状态机同步问题；M5 加状态时只加一组字段）。方向按 `MoveAxis` 翻转（不靠速度符号，空中急停不甩脸）。
- 碰撞盒：1×1 占位方块 → **0.5×1.6**（视觉 2m 高、盒略小保宽容）；终值以实现期实测 ±0.1 回填 ADR-0008。M1/M2 的 19+6 测试必须全绿作为手感无回归的兜底。
- 过渡期策略：生成器可先行按新盒生成关卡；玩家视觉接入前用深色方块占位，接入即替换，不阻塞关卡数据编写。

## 9. 背景视差规格

两层：`back.png`（128×240，远景天空/远林）+ `middle.png`（176×112，近林）。滚动因子 back ≈ 0.15、middle ≈ 0.4（相对相机），按关卡宽度平铺；各关用缩放/tint 变体做区分（实现期定），不引入新素材。

## 10. HUD 与过关统计

- 常驻 HUD：左上角樱桃图标（cherry-1 帧）+ 「x/y」计数（锚定决策 Q9 的极简方案；文本用 legacy `Text`，理由同 §6）。
- 过关统计：终点门触发后显示「本关樱桃 x/y」随淡出；通关画面显示累计「x/27」。
- `LevelManager` 接口（窄接口深行为，codebase-design）：

```
int Collected; int TotalInLevel;        // 只读进度
void RegisterCherry();                   // Collectible 调
void CompleteLevel();                    // LevelExit 调：冻结输入 → 统计 → 下一场景
static int TotalCollected;               // 跨场景累计（通关画面读）
```

## 11. 验收标准（M3 done）

1. 4 个关卡场景连续可通关：教学 → 关1 → 关2 → 关3 → 通关画面。
2. 每关具备：tilemap 正式地形、两层视差背景、相机边界、重生点、终点门、可选樱桃、HUD 计数。
3. Foxy 动画由状态机驱动、方向翻转正确、碰撞盒匹配视觉。
4. 所有机关使用正式外观（无占位色块）。
5. 教学关覆盖全部操作（移动/跳跃含可变跳高/下穿/弹簧/移动平台/尖刺与重生/樱桃/终点门）。
6. 全部测试通过：回归 19+6 + 关卡数据结构校验。
7. 用户逐关试玩验收（截图 + 反馈 → 迭代 → 编辑器微调 → 迁回关卡数据）。
8. README 勾选 M3；CONTEXT.md、ADR、本设计文档落盘。

## 13. 风险与待定项

1. **弹簧视觉**：已定方案 = block 类精灵 + 黄色 tint + `BumperVisual` 压缩-回弹动画；若试玩截图观感不佳，再换 crank 类 props 拼凑。
2. **fall 动画**：复用 jump 帧 2（已定，试玩时看是否观感可接受）。
3. **碰撞盒终值**：0.5×1.6 为提案，实测 ±0.1 微调，回填 ADR-0008。
4. **我无法目视验证**（本会话无图像输入）：每关初版需用户截图反馈闭环。
5. **樱桃摆放与难度**：初版按红线算好，具体手感靠试玩迭代。
6. **可达性校验**：v1 只做几何红线检查，全物理 BFS 可达性为可选增强，试玩兜底。
